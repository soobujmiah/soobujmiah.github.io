# SKB Knowledge Return Contract

**Status:** Active

This repository is authoritative for its own portfolio/site state. SKB is the owner's cross-project knowledge layer. When this repository is explicitly included in the SKB workflow and authenticated access is available, consult relevant SKB context before substantive decisions and review completed work for durable knowledge to return.

## Adaptive return
Do not use a fixed project template. Determine what knowledge is durable and reusable, then choose the best SKB destination, structure, document type, language, and level of detail according to SKB's existing organization.

Return meaningful portfolio/project-state changes, verified project relationships, durable presentation or architecture decisions, reusable solutions, important constraints or lessons, and other information useful across future work. Do not return routine noise, temporary debugging output, unsupported claims, credentials, tokens, private keys, cookies, or other secrets.

## Evidence and conflicts
Preserve provenance where practical and distinguish verified facts from observations, inference, recommendations, and unknown/stale information. Never silently overwrite conflicting SKB knowledge; preserve conflict or supersession information.

## Security and authority
Never store SKB/GitHub credentials here. Forks and clones do not inherit SKB write authority. Verify authenticated identity and actual write permission before a direct SKB write. This contract authorizes knowledge continuity only, not unrelated repository changes, releases, deployments, destructive actions, or credential operations. Explicit task restrictions take precedence.

## Legacy mode
Legacy mode is deferred and is not part of the current implementation.
