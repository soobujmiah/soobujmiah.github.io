Public evidence model

What is verified, experimental, and historical?

I keep technical portfolio claims explicit so a benchmark is not mistaken for a product capability, and an experiment is not presented as production-ready.

✓ Verified

Current capabilities supported by repository evidence, repeatable testing, or established professional experience.

  • Operations and office administration
  • Termux / PRoot Debian / X11 Linux workstation work
  • Local LLM workflows using llama.cpp and GGUF
  • Git/GitHub development and technical documentation
  • LAI CPU-side local inference and documented runtime architecture
  • Device diagnostics and runtime investigation

△ Experimental

Active, limited, device-dependent, or qualification-pending work.

  • Vulkan acceleration on the Redmi Turbo 4 Pro / Adreno 825 environment
  • GPU llama.cpp execution affected by the Qualcomm Vulkan driver path
  • NPU/QNN backend work before qualification gates are passed
  • Evolving AI-agent, RAG/OCR, and automation integrations

◷ Historical benchmark

Observed results from a defined past test or configuration. They are not guarantees of current production performance.

  • 465 FPS historical graphics/runtime benchmark
  • 8K context historical test/configuration claim
  • Other one-off measurements tied to a particular device, driver, model, build, resolution, or runtime
Rule: Verified means current public capability. Experimental means active or limited development. Historical benchmark means an observed past measurement with context. Private SKB information, credentials, secrets, and unsupported claims are never promoted merely for completeness.
