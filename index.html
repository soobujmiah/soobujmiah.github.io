04 — Technical Case Studies

Case 01

Native ARM64 Android APK Build & Packaging Pipeline

Project: ADT · Toolchain Engineering
Problem

Building and signing Android APKs natively on an ARM64 Linux environment without relying on an x86_64 PC or heavy Android Studio installation.

Investigation

Audited standalone ARM64 ELF build tools, JVM-based bytecode compilers (D8/R8), Android 35 platform SDK jars, and signature packaging utilities.

Evidence

Native aarch64 aapt2 linked Android 35 resources; JVM D8 (v8.2.33) compiled MainActivity.class into classes.dex; Debian Trixie apksigner 35.0.2-1 ran via JVM on ARM64 host.

Root Cause

Standard Google command-line tools distribute x86_64 binaries by default and return 404 for guessed ARM64 Linux URLs; signing tools require decoupled host JVM packaging.

Solution & Validation

Engineered an automated pipeline combining verified aarch64 AAPT2 binaries with JVM D8 and host apksigner. Tested via RSA-2048 keystore signing; apksigner verify --verbose --print-certs confirmed v1, v2, and v3 verification true on the assembled APK.

Outcome: Reusable, reproducible ARM64-native APK compilation and signing pipeline without desktop workstation dependencies.
Case 02

Android Vendor Vulkan Driver Crash Localization

Project: LAI · Driver Diagnostics
Problem

Opt-in llama.cpp Vulkan GPU generation suffered fatal process crashes on Qualcomm Snapdragon 8s Gen 4 (Adreno 825) during LLM token inference.

Investigation

Integrated native crash handler hooks in C++ (native_crash_handler.cpp) and symbolized tombstone logs using addr2line and NDK tools.

Evidence

Symbolized backtrace pinpointed SIGSEGV at vkCmdBindPipeline+0x4 inside vendor vulkan.adreno.so while ggml-vulkan.cpp:15635 binds the MUL_MAT pipeline.

Root Cause

Qualcomm vendor Vulkan driver crashes during matrix multiplication pipeline binding; cannot be caught or recovered safely from Java/Kotlin userspace.

Solution & Validation

Implemented a fail-closed execution boundary: disabled experimental Vulkan GPU offload by default and optimized multithreaded ARM64 CPU inference with KV-prefix reuse, maintaining rock-solid 12–20 tok/s generation without crashes.

Outcome: Guaranteed application runtime stability while maintaining transparent, evidence-backed driver qualification documentation.
Case 03

OpenGL Acceleration over Vulkan in No-Root PRoot Userspace

Project: Ternux · Graphics Virtualization
Problem

Running hardware-accelerated Linux desktop applications inside a non-root PRoot Debian container on Android without direct kernel DRI3 access.

Investigation

Tested userspace graphics translation stacks bridging OpenGL calls through Vulkan directly to the Adreno hardware device node (/dev/kgsl-3d0).

Evidence

Mesa Turnip Vulkan driver combined with Zink (OpenGL-on-Vulkan) achieved 465 peak FPS in glmark2-es2 benchmarks rendered over Termux-X11.

Root Cause

PRoot lacks kernel module permissions for direct DRI3 display devices; user-mode translation via Zink + Turnip bypasses standard X11 DRI3 limitations.

Solution & Validation

Engineered automated environment scripts (x.sh) setting Mesa driver flags, D-Bus system daemons, and TCP-routed PulseAudio to bypass Android background limits.

Outcome: Reproducible, high-performance Linux desktop environment with hardware-accelerated viewport rendering on an unmodified mobile phone.
Case 04

Deterministic Canvas State & Reversible History Architecture

Project: GGEN · Engine Architecture
Problem

Preventing state drift and data loss in a multi-column, linked text-flow canvas during complex undo/redo sequences and app restarts.

Investigation

Profiled mutation cycles across text-flow link chains, page geometry bounds, and storage commit boundaries under memory pressure.

Evidence

143 passing pure-Dart unit tests in packages/ggen_core verifying fail-closed link validators, cycle detection, and exact text length conservation.

Root Cause

Mutable node graphs cause inconsistencies during multi-frame text reallocation; non-transactional file writes risk corrupting project archives.

Solution & Validation

Architected an immutable document model with TextFlowEngine and atomic FileProjectStore writes backed by SHA-256 receipts. Verified on Redmi Turbo 4 Pro touch canvas.

Outcome: Robust, mathematically verified document and layout core ready for computer-quality studio workflows on mobile devices.
