# Pocket Systems — portfolio direction (2026-10-12)

## Evidence and concept

The portfolio follows a documented phone-first development chain: Android,
Termux, PRoot Debian, native ARM64 tools, device validation, and local AI.
The central object is therefore a computing spine, not a generic science
fiction city. Eight stations carry the visitor from identity through the
computing method, workstation, projects, research, experience, and contact.

The public Ternux, ADT, LAI, and GGEN repository descriptions and the
portfolio's evidence-backed `app/content.ts` govern project claims. SKB is a
private knowledge infrastructure project; this site identifies its purpose
without linking to private source or publishing internal content.

Reference: [Bruno Simon's portfolio](https://bruno-simon.com/?lang=en) shows
how one navigable world can carry a developer's work. The
[Three.js examples](https://threejs.org/examples/) informed restrained lit
materials and geometry. The scene design and forms here are original.

## Composition

- One continuously connected 3D route, with a chapter-specific instrument
  at each stop. Camera positions study those instruments rather than empty
  scenery. A connected signal route explains the sequence.
- The identity is actual extruded 3D lettering in English. Bengali uses DOM
  text because browser shaping is required for accurate glyphs.
- The chapter frame holds one short inscription at the lower scene edge.
  The full factual record opens below the frame on request, where evidence,
  links, and long copy stay selectable and accessible.
- The project scene contains five named instruments: Ternux, ADT, LAI,
  GGEN, and SKB. Ternux is a desktop on phone, ADT a build gantry, LAI a
  local inference module, GGEN layered document sheets, and SKB linked
  documents. Choosing one of the four public featured projects changes
  the camera focus.
- The workstation uses six visibly separated physical layers. The research
  bench distinguishes a validated CPU path from GPU/NPU qualification.
  The experience route contains eight chronological markers.
- Portrait screens show the object in the upper scene and its inscription
  below, with room for native scrolling. The footer and pager retain clear
  space. Reduced motion keeps the camera static per chapter.

## Fallback and verification

WebGL loads lazily. Failure switches to the existing Canvas2D environment;
without JavaScript the static routes retain readable HTML and a CSS ground.
The WebGL scene is decorative for assistive technology. The DOM supplies
semantic headings, links, Bengali shaping, and the complete evidence record.

Repository gates and GitHub Pages deployment results are recorded in the PR.
The owner requested that local visual browser testing be skipped and will
review the deployed site manually. This document does not claim that a
successful build proves visual acceptance.
