# SEO Plan — Sobuj Miah Portfolio

Research date: 2026-11-24. This is an intent-based keyword map built from current search results and the project's own evidence. It is not a traffic-volume forecast; use Search Console after launch to see which queries actually appear.

## Positioning

Sobuj Miah is an independent software and AI systems engineer, web developer, and office administrator in Savar, Dhaka, Bangladesh. The strongest differentiators are:

1. **Linux on Android with Termux** — Ternux, Ternuxx, and the Linux workstation service.
2. **Local AI on Android** — LAI, llama.cpp, GGUF, and CPU-first inference.
3. **ARM64 Android tooling** — ADT, built from AOSP and validated on real hardware.
4. **Practical software and web work** — websites, custom tools, Flutter, Android.
5. **Dependable operations support** — office administration, data entry, computer support.

The site should win queries where the intent is a **tool, a setup, a service, or a person** — not generic “what is Linux” articles.

Keyword coverage is layered rather than repeated: a small brand-and-intent set at the site level, a narrower set on each shared page, and a project-specific vocabulary on each project page. Nothing is stuffed into a page where it does not belong — a term only appears where the page actually answers that query.

## Internal linking

Two mechanisms keep crawl depth shallow and give every page a descriptive inbound link.

1. **The bottom dock** links all eight top-level pages from every route.
2. **The next-page band** closes each top-level page with a link to the next one in reading order (Home → About → Services → Projects → Experience → Research → Evidence → Contact), using the destination page's real `h1` as the anchor text rather than "next". That gives every page in the chain a keyword-rich internal link, and it also gives a visitor who scrolls to the end an obvious way to keep going.

Project and service detail pages already carry their own prev/next or related links, so they do not repeat the band.

## Project sites as entities

Ternux and ADT each ship their own GitHub Pages site. The content model carries a `website` field for them, which appears in three places:

- a "Visit website" link on the projects grid,
- a primary button on the project detail page, with the repository demoted to a quiet button,
- `sameAs` on the project's `SoftwareSourceCode` JSON-LD, which tells search engines the code record and the live product are the same thing.

Only projects that really have a live site get the field — linking a repository to a page that does not exist would be worse than not linking at all.

## Profiles and entity signals

The contact page lists 21 profiles in five typed groups. Every one of them also lands in the `Person` node's `sameAs`, which is the strongest available hint that these scattered accounts belong to the same person — useful for a name that shares space with other people.

Only real, resolvable profile URLs are listed. A `sameAs` entry pointing at a page that does not exist is worse than omitting it.

## Measurement

- Search Console: filter queries for `linux on android`, `termux`, `llama.cpp android`, `web developer dhaka`, and `office administrator dhaka`.
- Track clicks, impressions, and average position for the Ternux, LAI, ADT, services, and contact pages.
- Use Bing Webmaster Tools for a second index signal.
- Validate structured data with Google's Rich Results Test and Schema.org validator.
- Check Core Web Vitals on mobile; the site has no 3D runtime and a small JS budget.
- Review the query map quarterly. Add content only where there is real evidence and a clear intent.

## What not to do

- Do not stuff keywords into copy. Keep the writing natural and specific.
- Do not invent metrics, testimonials, client names, or performance numbers.
- Do not guarantee rankings or traffic.
- Keep GPU/NPU claims labelled experimental until they are validated on the named device.
- Do not create thin pages for every keyword variant. The current 50 routes cover the intent clusters with substantial content.
